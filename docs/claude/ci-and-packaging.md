# CI and Packaging

Moved word for word from the "CI and Packaging" section of the project's `CLAUDE.md` on 2026-10-26, when that file was cut down to a short root that indexes these notes. Where the text below says "this file", it means the project's notes as a whole: `CLAUDE.md` and the files in `docs/claude/`. Section names the code and README use ("Key Patterns", "Known Gotchas", "Module Map") name the folders of `docs/claude/`. Each paragraph is one line, some of them long: find one with `grep -n`, then read that line by number.

- `.github/workflows/ci.yml` runs two jobs, **Lint (ruff)** and **Test (pytest)**, on every push to `main` and on every pull request regardless of base branch (the `pull_request:` trigger carries no branch filter). Both must pass before merging — run them locally first.
- `.github/workflows/claude.yml` runs Claude (`anthropics/claude-code-action@v1`) on any comment, inline review comment, review or issue that mentions `@claude`. The action passes Claude an inline comment's text but not its file, line or code, and it lists only the review comments posted before the one that triggered it, which leaves out the triggering comment itself and every inline comment of a triggering review. So for an inline comment, or a review with inline comments, a step before the action (`Note where the inline comments are`) writes each comment's file, lines and the diff GitHub shows with it (and, for a reply, the earlier comments of its thread) to `.git/claude-review-comments.md`, and `claude_args: --append-system-prompt` tells Claude to read that note first. The repo is public and the step runs before the action checks who commented, so it only reads comments with `jq` and writes them to the note, never running anything from one. The action's token exchange checks the workflow against `main`, so a change to `claude.yml` can only be tried once it is merged.
- `pip install -e ".[dev]"` installs the packages CI needs. Backtests additionally benefit from the optional `perf` extra (`pip install -e ".[dev,perf]"`), which adds `orjson` to speed up settled-market JSON parsing — never required, and the on-disk cache format is identical with or without it.
- **Package discovery is explicit:** `pyproject.toml`'s `[tool.setuptools.packages.find]` includes only `kalshi_betting*`. Without it, setuptools' flat-layout auto-discovery treats every top-level directory named like a Python identifier as a package, and a checkout that has run a backtest also has `backtest_cache/` at the root. So `pip install -e ".[dev]"` refused to build ("Multiple top-level packages discovered in a flat-layout") on exactly the machines that run backtests, while CI's fresh checkout never saw it. Pinned by `tests/test_packaging.py`; don't remove the table or widen its pattern.
- `pyproject.toml` declares `requires-python = ">=3.11"` and pins `kalshi-python-sync==3.2.0`. Do NOT bump the SDK pin to 3.13.0 — that version's own metadata requires Python >= 3.13 and breaks `pip install -e ".[dev]"` on 3.11 (i.e. breaks CI).
