**Dependency order (no circular imports):**
```
config.py, _http.py
  └─ run_lock.py (config only) ─→ main.py, scheduler.py, defaults_server.py
  └─ auth.py, scanner.py
       └─ strategy.py
            └─ reporter.py
                 └─ trader.py (imports reporter.TradeResult)
                      └─ main.py, scheduler.py

historical.py → auth.py (build_client, wrapped by build_historical_client/build_prod_live_client)
main.py → historical.py (load_series_categories, series_labels, infer_category — every run files each market by them for the same-title sport check, DR-79; the live category/tag filter files a pair by the backtest dashboard's own rule, and a run started with --result-file records each trade's category and tag by it)
dashboard.py → historical.py (series_labels, the one filing rule the live filter shares)
historical.py → scanner.py (event_series, the ONE definition of an event's series identity, so the event-title fallback's combo test — DR-51 — can never disagree with the one-series rule about what a combo is; event_competition, the ONE reading of an event's competition label, so load_event_competitions reads the backtest's labels as live ingest reads them, DR-79)
historical.py → backtester.py → dashboard.py → backtest.py (backtester reads historical's series_labels, load_series_categories and load_event_competitions for the same-title sport check, DR-79; backtest.py reads the /series listing once and hands it to both run_backtest_sweep and generate_dashboard)
auth.py → backtest.py (read_account_balance: the backtest's starting balance when --balance is not given); _http.py → backtest.py (api_error_summary: the one-line reason a failed balance read stops the run with, and a failed save or load of the saved sweep file is reported with); backtest.py also reads, as text, the source files of backtester, strategy, scanner, depth_model, historical and config, to fingerprint the simulator code a saved sweep came from
eda.py → backtest.py (build_eda_page: the Data page, rebuilt after the backtest page on a full run and on --dashboard-only unless --no-eda; the only import of eda in the package)
historical.py → treasury.py (CACHE_DIR, _exception_summary, _load_json_cache, _save_json_cache — the same cache idioms load_series_categories uses); treasury.py also imports config.py and _http.py, like every other leaf-adjacent module. treasury.py → dashboard.py (RiskFreeRates and SOURCE_CACHE: generate_dashboard(risk_free=...) and its header line; day_numbers, the one day numbering the yield lookup and the deployed-capital lookup share); treasury.py → backtest.py (load_risk_free_rates(), called after the sweep and handed to generate_dashboard(risk_free=))
backtester.py → scanner.py (time_series_group_key, the ONE definition of the time-series grouping key — title + outcome label — shared with the live scanner; event_series, the ONE definition of an event's series identity, so the one-series rule can never disagree; leg_sides, so _settlement_receipt pays by the side each leg bought; deadline_profile/cumulative_deadline_pair, the ONE definition of a two-cumulative-deadline pair; deadline_pair_refusal and its REFUSED_SNAPSHOT/REFUSED_NO_STATED_DEADLINE/REFUSED_SAME_DEADLINE constants, so _extract_pairs's DR-72 refusal-reason skip counts mirror the live finder's; stated_deadline/same_event_ladder and its SAME_DAY sentinel, the ONE definition of which calendar day a rung's deadline names and of how two rungs of one event are ordered and gapped, so the DR-73 ladder rule can never disagree between the paths; closes_apart, the ONE definition of the same-title close gate, so the DR-74 rule can never disagree between the paths about which cross-series pair closes at one moment, and close_gap_bound_text, the bound its refusal line prints, read from the same scanner binding so the two paths' lines stay verbatim twins; ladder_keys, the ONE definition of which ladders a market is on, so the DR-76 one-open-trade-per-ladder rule uses the same labels on both paths — its inputs can still differ: a cached market without an event title has a wider question label than it would live, see the DR-76 backtest residuals; labels_differ and competitions_differ, the ONE definitions of the same-title sport check, so the DR-79 rule can never disagree between the paths about which two series or two competitions are one question)

backtester.py → strategy.py and scanner.py (compute_trade, and scanner._enrich_pair with CandidatePair, HeldPair, _market_from_dict and leg_prices: the live sizing code every trade is sized with, over a synthetic book; and scanner._cash_binds, enrichment's test of whether the cash sets a budget, which the backtest counts its cash-bound skips by; backtest-only, since no live module imports backtester); backtester.py → depth_model.py (DepthModel, volume_24h, book, bid_ladder, can_start_at); backtest.py → depth_model.py (load_depth_model, called before the fetch and handed to run_backtest_sweep(depth_model=))

depth_model.py — backtest only; imports config.py, _http.py (api_error_summary), scanner.py (fetch_open_events_with_markets, _fetch_orderbook, event_series, fetch_shard_statuses, inactive_shard_indexes) and historical.py (CACHE_DIR, fetch_candlesticks, series_ticker, build_prod_live_client), never trader, strategy, reporter or main; imported by backtester.py and backtest.py only, never by a live module (tests/test_depth_model.py::TestIsolation, tests/test_strategy.py::TestTimeSeriesKellyParity::test_ast_no_live_module_imports_the_depth_model); its snapshot command is human-run and sends read-only GETs
market_details.py — backtest only; imports config.py, _http.py (api_error_summary) and historical.py (the retried read-only signed GET, the cache folder and gzip JSON helpers, series_ticker, the client builder), never scanner, trader, strategy, reporter or main; imported by backtester.py only, never by a live module (tests/test_market_details.py::TestIsolation); its capture command is human-run and sends read-only GETs
eda.py — reporting only (counts what backtest_cache/ holds and draws the Data page); imports config.py, glossary.py, historical.py (_day_store_iter, _SliceUnreadable, _iso_epoch, _read_title_file with _TITLE_FILE_ABSENT, the file names of _EVENT_TITLES_CACHE and _CANDLES_DIR, series_labels, series_ticker, infer_category, usable_candle_ask) and scanner.py (event_series, deadline_profile, stated_deadline) at module level, and backtester.py and dashboard.py only inside khat_view and plotly only inside _plotly (so its worker processes never load pandas or plotly on its account), never an order-path module (trader, main, scheduler, run_lock, defaults_server, v2_probe, seller); imported by backtest.py alone (build_eda_page, called after the backtest page on a full run and on --dashboard-only; tests/test_eda.py::TestIsolation), never by a live module — live_dashboard.py serves the page it writes without importing it
glossary.py — reporting only (the dictionary of the dashboards' scores); imports the standard library alone; imported by dashboard.py (the backtest page's Terms link and last section) and by eda.py (the Data page's Terms link and last section), never by an order-path module (tests/test_glossary.py::TestIsolation)
seller.py — imports config.py, scanner.py (the order book, the bid walk, settlements, held positions, for plan_trims the fill times, the bid floor and a held pair's kind, and for plan_add_ons the fill times and listed_ask) and historical.py (bid_before, recent_candles, and for plan_trims and plan_add_ons ask_before, and for plan_trims candle_reads_bid) only: never backtester, depth_model, trader, strategy, reporter or main; imported by main.py alone (plan_sales, plan_trims and plan_add_ons, before any purchase). trader.py and reporter.py read its SalePlan by its fields without importing it (tests/test_seller.py::TestIsolation)
v2_probe.py — standalone, human-run; imports _http/auth/config/scanner/trader, imported by NOTHING
defaults_server.py — standalone, human-run; imports config and run_lock only (never main, trader or any pipeline module: it starts main.py as its own process), imported by NOTHING (start_dashboard.sh runs it in the background, beside live_dashboard.py)
live_portfolio.py — reporting only (the live dashboard's Live trading tab); imports config, auth (_positions_value_cents), historical (_historical_get with _API_PREFIX, its only way to Kalshi: read-only GETs; _candle_close, _load_json_cache, _save_json_cache, series_labels, infer_category), reporter (PROD_LOG_PATH, the trade log's place), dashboard (_sharpe, _sortino), treasury (RiskFreeRates) and _http (api_error_summary), never trader, main, scheduler, run_lock, defaults_server or v2_probe; nothing in the trading pipeline imports it (live_dashboard.py does)
live_dashboard.py — standalone, human-run, read-only (the dashboard's three tabs: the Live trading tab on 127.0.0.1:8766, the backtest page and the Data page on 127.0.0.1:8767); imports config, live_portfolio (build_live_view, append_snapshot, trade_log_paths, OTHER_BETS), historical (build_prod_live_client, load_series_categories), treasury (load_risk_free_rates, RiskFreeRates, SOURCE_CACHE) and _http (api_error_summary), never trader, main, scheduler, run_lock, defaults_server, v2_probe or eda (a subprocess test checks sys.modules); imported by NOTHING (start_dashboard.sh starts it as its own process, in the background)
```
