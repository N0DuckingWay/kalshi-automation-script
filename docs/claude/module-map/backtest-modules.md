`_parse_fee_multiplier` accepts only a finite real number from 0 to 1, so a bool, a string, NaN, a number outside 0 to 1 or a missing value is unknown and left out, which readers charge as 1.0, the full fee, and `_fee_type` keeps the fee type text; the one exception is opt-in, keyword-only `upgrade=True` (`backtest.py` passes it, the live run modes never do): a file the categories reader would serve as current (younger than `max_age_seconds` with a non-empty `"series"` block) that has no `"fees"` block is upgraded by one fetch of the 19 MB listing through the retried GET, which a live run must not wait on, so a live run reading an old file without fees gets `{}` and every market the full fee (the safe direction: a fee is never lowered by a multiplier it could not read) until the weekly refresh writes the block; `None` when a request fails) |
| `treasury.py` | Downloads the 8-week Treasury bill's auction yields from the Treasury's Fiscal Data API — one open, no-key, read-only GET, retried like every other market-data read and cached under `backtest_cache/treasury_bill_rates.json` — for the backtest dashboard's Sharpe and Sortino ratios to subtract, on each day of a curve, the yield of the most recent auction on or before that day. Never raises: on any failure it falls back to the last saved download, and with none to `SOURCE_UNAVAILABLE` (the dashboard then subtracts 0% and its header says so). REPORTING ONLY — nothing sizes, prices or settles on it, and no order-path module may import it (`live_portfolio.py` does, for the Live trading tab's ratios, and `live_dashboard.py` downloads the yields with `load_risk_free_rates()`; both only read). `dashboard.py` imports `RiskFreeRates` and every ratio on the page subtracts it (`generate_dashboard(risk_free=)`), a strategy curve's on its capital in open trades only, reading the curve's dates as `day_numbers` once for both the yield and the deployed capital; `backtest.py` calls it after the sweep, just before the dashboard, and hands the result in | `RiskFreeRates` (`annual_on()`, `annual_on_days()`), `day_numbers()`, `load_risk_free_rates()`, `SOURCE_API`, `SOURCE_CACHE`, `SOURCE_UNAVAILABLE` |
| `depth_model.py` | The backtest's model of order-book depth. Backtest only: no live module imports it; `backtester.py` (`volume_24h`, `book`, `bid_ladder`, `can_start_at`, `DepthModel`) and `backtest.py` (`load_depth_model`) do. Kalshi keeps no historical order books, so it saves snapshots of live books, fits a table of how many contracts rest near the best bid, and builds a synthetic book from that table for any market and moment. `snapshot()` samples up to `config.DEPTH_SNAPSHOT_MARKETS` open non-combo markets, reads each one's book and its last 25 hours of candles, and saves them under `backtest_cache/depth_snapshots/<UTC stamp>.json.gz`; every request is a read-only GET and nothing here can place an order. `fit()` files each bid ladder, YES bids and NO bids alike, by the market's 24-hour volume and the ladder's best bid, and keeps the median contracts resting within each of `config.DEPTH_MODEL_DISTANCES` of the best bid; a cell with too few ladders reads its volume row, then the whole table. `volume_24h(candles, ts)` is the one definition of a market's trailing volume: `snapshot()` saves it with each book and the backtest reads it from each market's candles at every checkpoint and at each daily check before a sale. `book()` makes a synthetic book, in `scanner._fetch_orderbook`'s shape, whose top levels reproduce the quoted prices; the backtest sizes each trade over it. `bid_ladder()` builds one side of that book, and the ladder a backtest sale walks; `can_start_at()` says whether it can start at a bid (1c to 99c). `load_depth_model()` fits every saved snapshot (logging `Depth model loaded from saved snapshots: …`) and returns `None`, with a WARNING, when none is usable; `backtest.py` calls it before the fetch, and `run_backtest_sweep` logs the model the run used (`Depth model: …`). Run `python3 -m kalshi_betting.depth_model snapshot [--markets N]` to save one | `DepthModel`, `volume_24h()`, `fit()`, `bid_ladder()`, `can_start_at()`, `book()`, `load_depth_model()`, `snapshot()` |
| `eda.py` | Backtest-side reporting: counts what `backtest_cache/` holds, for an exploratory data page. Each day slice in `archive_days/` and `live_days/` is read once (streamed through `historical._day_store_iter`) and boiled down to a small JSON summary at `backtest_cache/<config.EDA_SUMMARY_DIRNAME>/<archive|live>/<day>.json`, written atomically by the parent process and reused while its key — the slice's kind, day, size, `st_mtime_ns`, meta `cutoff_ts` (archive; read from a streamed slice's first line, a legacy slice compared on size and time alone) and `config.EDA_SUMMARY_VERSION` — still matches; a damaged saved summary is simply rebuilt. A slice that cannot be read, or changes while it is read, gives a summary naming it in `unreadable` (`"<file name>: <one-line reason>"`, nothing counted), which is never saved, so the next run tries it again, and nothing else stops; a slice folder that exists but cannot be listed is named the same way and its saved summaries are left alone. An archive summary counts only records settled before its own slice's `cutoff_ts` (the rule `historical._assembled_records` applies) and counts the rest in `dropped_after_cutoff`. With M the largest cutoff among readable archive summaries, a live day counts only when it ends after M (so a fetch interrupted between the archive refetch and the prune counts no day twice), and a live day's summary is kept, and counted, after its slice is deleted until M reaches the end of its day (`historical._extend_assembled_cache` deletes the live days before a new cutoff without fetching the archive again); a gone archive slice's summary and a leftover `<day>.json.tmp` are deleted. No ticker is de-duplicated (see the module Notes for what can still count twice). A summary's counters are keyed `"week|combo|series"`: the Monday (UTC) of the settlement week (`"unknown"` when it cannot be read), combo `scanner.event_series(...) == config.MVE_SERIES_FAMILY_PREFIX`, and the literal series ticker (`historical.series_ticker`); each holds n, yes, no, other, blank subtitle, blank event title before and after the `event_titles_v2.json` join, no readable open time, a lifetime histogram (`config.EDA_LIFETIME_EDGES_HOURS`) and a settlement-lag histogram (`config.EDA_LAG_EDGES_HOURS`, its first bucket the markets settled before their close), the tick regimes and the shards, and, for non-combo records only, the `scanner.deadline_profile` verdicts. Non-combo cumulative records' `scanner.stated_deadline` days are kept per event, and each record whose ticker has a candle file is kept as `[result, close_time, settlement_ts, series, combo]`. `merge(summaries, *, series_categories, candle_set=)` files each series under `historical.series_labels` (with `infer_category` as the fallback) from the listing it is handed, adds the counters under `"week|combo|category|tag"`, counts a ladder (an event with two or more distinct stated days, filed under its earliest day's month) whose rungs sit in different slices, counts the candle files with no joined market, and returns `coverage`: the archive cutoff M against the first and last live day counted, the gap in days, the live days skipped and kept without a slice, and a one-sentence note. Residuals: a candle file created after its slice was summarised is not joined until that slice is rebuilt, and `blank_title_after`, the deadline wording and the ladders read `event_titles_v2.json` as it was when the slice was summarised. Built in this process with `workers=1`, otherwise in up to `config.EDA_MAX_WORKERS` spawned worker processes, each of which loads the event titles and the candle tickers once (`_init_worker`); a spawned worker imports the caller's main module again, so a caller must build under `if __name__ == "__main__":`. Workers that do not answer a trivial task within `config.EDA_WORKER_START_TIMEOUT_SECONDS`, a pool that cannot be made (a sandbox refusing new processes) or breaks are killed and shut down without waiting, with one WARNING, and the remaining slices are counted in this process. Workers still busy `config.EDA_BUILD_DEADLINE_SECONDS` (3600) after the pool is started are killed the same way, with one WARNING, but the slices left are not counted in this process: each is named unreadable (`NOT_SUMMARISED_IN_TIME`, "not summarised in time"), never saved, so the next build reads it again; every backtest reaches this build, so it has a deadline (the in-process path has none). The build logs one INFO line before it reads anything (`Data page: summarising day slices: N to read, M reused from earlier builds`), one every `config.EDA_PROGRESS_EVERY_SLICES` slices summarised, and its end line. Three more readers sit beside the day-slice counts. `summarise_candles(cache_dir, candles)` (`candles` is `merge()`'s candle map) lists `candlesticks_v3/` (`historical._CANDLES_DIR`, gzipped `<ticker>.json.gz` files, `historical._CANDLE_FILE_SUFFIX`) once with `os.scandir` and reads each file whose saved facts no longer match: for each lead in `config.EDA_PRICE_LEADS_HOURS` (1, 24, 168 hours) the YES ask (the primary price: what betting Yes costs) and the midpoint, (YES ask + (1 − NO ask)) / 2, of the last candle whose end `ts` is at or before close minus the lead, each kept only when `historical.usable_candle_ask` accepts it (a NO ask at the 0.99 clamp or a YES ask of 1.0 is no quote) and only where the book was at most `config.EDA_MAX_BOOK_WIDTH` (10c) wide: the YES ask minus the YES bid (1 minus the NO ask), a missing bid counting as 0 — a 99c ask with no bid only says nobody sold lower (on the real cache, of the 24 h prices of 95c or more whose book had no YES bid, only 251 of 3,526 settled Yes, against 1,243 of 1,268 where the book was at most 10c wide), so it gives no price at all, while a long shot asked at 3c with no bid is 3c wide and counts. A long shot's YES bid is under a cent, so its NO ask sits at the clamp: it has an ask but no midpoint, which is why the midpoint alone dropped most long shots. A candle that ended more than `config.EDA_PRICE_MAX_AGE_HOURS` (24) before the lead's moment gives no price (the lead is `stale`). `close_time` is the REALIZED close, so where trading carries on after the outcome is known the 1 h price can already reflect it. Also kept per file: the traded volume (summed over the candles that state one), the field version (a file with no `fields` key is version 1) and whether the file is empty. The facts are cached per file name in `<cache>/eda_days/candles.json` with the file's size, `st_mtime_ns`, the close time text used and their own `config.EDA_CANDLE_FACTS_VERSION` (and the leads and the maximum age), so changing the facts never rebuilds the day-slice summaries; a file is read again when any of those changes or its saved entry is not well formed (`_fact_matches` checks every field), while a changed result or category needs no re-read (the join with `merge()`'s map happens after the cache); a failed save is a WARNING. Joined non-combo markets with a yes or no result are filed per lead and category, for both the ask and the midpoint, into `config.EDA_CALIBRATION_BIN` (5c) price bins with the count and the Yes count (the reliability chart and the favourite–longshot gap) and the Brier sum and count; `coverage` counts per lead those markets, how many have no ask, no midpoint, a book too wide to price (`wide`; such a market is not also counted in `no_ask` or `no_mid`) and a stale price. The columns overlap: stale ones are also counted under no ask, and every market with no ask is also under no midpoint, while a wide book is in neither; the page's table adds a Priced (ask) column, markets minus no ask minus wide book, and says so in its caption. Residual: a real 1c YES bid reads as no bid (its NO ask sits at the clamp), so a book 10 to 11c wide with a 1c bid counts as wide. A reliability dot and a gap bar sit at the average price of the markets in the bin (each bin keeps `[markets, yes, price sum]`), not at the bin's centre. Volume per category counts only files at `config.CANDLESTICK_CACHE_FIELDS_VERSION`; combos are counted and left out (`combos_left_out`), and every file is counted by field version, empty, unreadable and unjoined; a file that cannot be read is skipped, never raised. Measured on the real cache (102,104 files, 33,312 of them combos, 1,210 unjoined, 638 empty): 23 s for the first pass, 0.9 s when the facts are reused. `inventory(cache_dir)` gives one row per top-level entry of the cache folder (name, folder or file, files, bytes, the oldest and newest `<YYYY-MM-DD>.json[.gz]` inside, a plain description from `INVENTORY_DESCRIPTIONS` or `INVENTORY_NOT_DESCRIBED` for anything unknown, `detail`, `error`): one `os.scandir` pass per folder (the depth snapshot folder's count comes from the same pass; names starting with `.` are left out, and `event_titles.json` is described as the older title file), only the first line of each `settled_markets_*.jsonl.gz` (its meta: start date, filter tag, assembled at, assembly counts; a damaged line gives `meta_error`), the snapshot count and newest time (from the file name) for `depth_snapshots`; it never raises. `khat_view(sweep, *, series_categories=None)` reduces `sweep.calibration`'s observations to the k view: mid-spread bins of `config.EDA_KHAT_SPREAD_BIN` with the realised in-between rate, and k̂ with its `config.KHAT_CONFIDENCE_LEVEL` interval pooled, by gap band and by category, through `backtester._calibration_bucket` and `dashboard._khat_interval`/`_khat_cluster_sums`, so each figure equals the backtest page's; it reads the primary band's calibration through `dashboard._primary_calibration`; `backtester` and `dashboard` are imported INSIDE it, so the spawned summary workers never load pandas or plotly (the isolation test allows exactly those two local imports); `save_khat`/`load_khat` keep it as strict JSON in `<cache>/eda_days/khat.json` with a `version` (`config.EDA_KHAT_VERSION`; a NaN raises before anything is written; a missing, damaged or non-strict file, or one of another version or none, loads as `None`, and the page draws the k block inside its own try, so a saved view in an unexpected shape costs that block alone and the census and ladder charts stay). The Data page: `build_eda_page(*, sweep=None, series_categories=None, workers=1, cache_dir=None, out_path=None)` runs `load_or_build_summaries` and `merge` (with the listing, or the cached copy via `historical.load_series_categories(None)` when none is given), then `summarise_candles` and `inventory`, takes the k view from `khat_view(sweep)` (and `save_khat`s it) or, with no sweep, from `load_khat`, and writes `config.EDA_DASHBOARD_FILENAME` under `config.PROJECT_ROOT` (both defaults read at call time; `cache_dir` defaults to `historical.CACHE_DIR`) to a temporary file renamed into place. It never raises: a step that fails is one WARNING with its traceback and a line in an amber box at the top of the page, the section that needed it says so, and the rest is still written (`None` only when nothing could be written); the day files and the candle files are separate steps, so a candle failure keeps the day counts. The page has the title, the Terms link (`glossary.terms_link_html(PAGE_DATA)`), a line `Built <UTC time> from N day files (R records)`, then six sections in order: Inventory (the `inventory()` rows: Item, Files, Size, Dates, What it is, with the corpus meta or snapshot facts in brackets, and a note that corpora and candles are filtered), Market universe (a Non-combo / Combo / All switch, Non-combo by default, over markets settled per week by category (the eight largest and More), share settled Yes by category (horizontal bars, largest first, categories with no settled Yes or No market left out, n in the hover) and by month (a category's month with fewer than `config.EDA_MIN_MARKETS_PER_POINT` markets left out), lifetime and settlement-lag histograms, tick regime and shard share over time; the coverage note of `merge()` prominently, amber when there is a gap; the candle volume by category below the switch, since candles are non-combo), Price calibration (a Lead switch, 1 h / 24 h / 7 d, and a Price switch, Yes ask / Midpoint, over a reliability chart (with a note that a price counts only where the Yes ask–Yes bid gap was 10c or less), the favourite–longshot gap and a Brier-by-category table, plus a per-lead coverage table with a Wide book column; no Combo switch, with the reason), Deadline ladders and k (the wording census by category, ladders per month, and the k view: mid-spread bins against the in-between rate with the lines y = k̂ x and y = k x, and k̂ with its 95% CI by gap band and by category, `khat_view`'s figures as given; "No backtest has saved its k figures yet." when none), Data quality (a Combo switch over the share of records missing a subtitle, an event title before and after the join and an open time, then the day-file, candle-file and depth-snapshot counts and the unreadable day files by name) and `glossary.terms_section_html(PAGE_DATA)`. Every word is a module constant; every table cell is escaped. A switch is a group of buttons with `aria-pressed`; Python draws one `<div>` per option (all but the default `hidden`) and the page's one small script (`_SCRIPT`, about 35 lines, no `innerHTML`) writes only `hidden` and `aria-pressed` and asks `Plotly.Plots.resize` for the charts of a view it reveals (quietly nothing if Plotly did not load). The charts are plotly.py figures with no template and no copy of Plotly, embedded with `full_html=False`; the page loads Plotly once from `config.LIVE_DASHBOARD_PLOTLY_URL` with `LIVE_DASHBOARD_PLOTLY_SRI`. plotly is imported inside `_plotly()` only, so the summary workers never load it. Size: a small fixture page is about 60 KB; a synthetic page of 280 weeks, 15 categories and every view is about 0.46 MB. `python3 -m kalshi_betting.eda [--workers N]` (`main()`) rebuilds the page from the cache without a backtest, logging to a rotating `kalshi_eda.log` beside the other logs, reusing the saved k view, and prints the page path (exit 1 if none could be written); it must stay under `if __name__ == "__main__":` because the workers are spawned. Each backtest rebuilds the page after its own (`backtest._build_data_page`, on a full run and on `--dashboard-only`, with the run's sweep and listing and `min(--sell-workers count, config.EDA_MAX_WORKERS)` workers; `--no-eda` skips it), and the live dashboard serves it as its Data tab (`/eda/` on `config.LIVE_BACKTEST_PORT`, read from disk; `live_dashboard` does not import this module).
